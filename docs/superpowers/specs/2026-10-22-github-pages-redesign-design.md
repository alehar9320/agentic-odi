# GitHub Pages Redesign — The Product Site

**Date:** 2026-10-22
**Status:** Approved (session decisions 2026-10-22; all builder questions settled)
**Scope:** `website/` — the public GitHub Pages site for Agentic ODI
**Supersedes:** `2026-10-18-github-pages-design.md` (the single-page era)

---

## Intent & Why

`README.md` is the project's front door for contributors. The Pages site is the front door
for everyone else: a PM who clicked a link, a developer deciding what to wire an agent to,
a skeptic deciding whether this is real.

The 2026-10-18 site answered "is this real?" adequately. It cannot answer "what is this,
what can it do, and how do I use it?" — because the product moved on and the site did not.
The site is now 57 commits behind `main`, and it is **factually wrong in three places**
(section 1). The design goal is no longer "a well-crafted single page"; it is a
**state-of-the-art product site** that carries the full weight of what Agentic ODI now is.

The Jobsian constraint that shapes everything, unchanged: **over-promising on an
experimental product is the one thing Jobs never did.** No dates, no maturity theater, no
CTAs that dead-end behind auth, no fake screenshots, no vaporware. The product is
experimental and the site says so out loud.

Definition of done: the published site is a single cohesive dark experience that shares its
visual DNA with the shipped Living Studio, demonstrates the product rather than describing
it, and documents every surface the software actually has — with all reference content
generated from source so it cannot drift.

### 1.3 Defects in the current build

- Copy buttons are **dead**: HTML uses `.copy_btn`, `main.js` queries `.copy-btn`.
- The scroll-reveal observer adds a `.revealed` class that **no CSS rule defines** — the
  effect is a no-op.
- **Dark mode is broken**: the page hardcodes light-mode hex values inline
  (`#1d1d1f`, `#6e6e73`, `#0062c4`, `#f5f5f7`, `#0071e3`) that never adapt.
- **Three conflicting palettes** in play: CSS custom properties, inline HTML hex, and the
  OG-art palette. They share no colors.
- `<title>` is `"Agentic ODI — Agentic ODI"`. The meta description is a **truncated
  sentence** — `"Agentic ODI explores how the Model Context Protocol"`.
- The `<h1>` sits **above** `<header>`, outside every landmark.
- `--color-bg-dark` / `--color-fg-dark` are declared and never used; the dark scheme
  swaps the light tokens in place instead.
- `.grid` and `.s-0`…`.s-7` exist in CSS and are never used.

### 1.4 Site-contract drift

`website/index.html` is **generated by `website/tools/sync-readme.py`**, which embeds the
entire page as Python string literals. The copy, the sections, and the honesty contract
are therefore pinned in a build script, and the site's headline claim is derived from
"the first prose line of the README, cut at the first `(`" — which is why the description
is truncated.

## 2. Decisions

All seven were settled in session on 2026-10-22. They are binding.

| # | Decision | Choice | Rejected alternative |
|---|---|---|---|
| 1 | Architecture | Python static-site generator (Jinja2 + markdown-it-py + Pygments). **No Node in the Pages path.** | Hand-written HTML (drifts); Astro (still needs a Python extraction step, adds a second toolchain) |
| 2 | Scope | Landing + full docs hub | Landing only; docs + changelog |
| 3 | Hero centerpiece | **Interactive scripted demo** in a device frame | Static renders; both |
| 4 | Theme | **Dark-only**, sharing the Studio's tokens | True dual theme |
| 5 | Audience | **Dual — PM first, developer quickstart immediately after** | Developer-first; PM-only |
| 6 | Copy | Keep H1 + sub + the three problem beats **verbatim**; refresh "How it works" and "Status" | Full rewrite; keep everything |
| 7 | Domain | Stay on `alehar9320.github.io/agentic-odi/` | Custom domain |

### 2.1 Why a Python generator, given GitHub Pages

GitHub Pages has **no runtime**. The constraint is on the *output* (static files), not on
the tooling: a build step runs in Actions and uploads the artifact. All three candidate
architectures are Pages-legal. The deciding factor is **anti-drift**.

The docs hub's reference content lives in Python source: 30 MCP tools
(`packages/core/.../contract.py`), the CLI command tree (`apps/cli/.../cli.py`), 17
connector presets (`packages/connectors/.../catalog.py`), the ODI entity schema
(`packages/core/.../schema.py`). Astro or Vite would **still** need a Python script to
extract that, then a JSON handoff into a second toolchain. One language, one lockfile, one
CI path.

This is also a pattern the repo has already proven: `make_og.py` renders `og.png`, the PNG
is committed, and `test_make_og.py` asserts the committed bytes are pixel-identical to a
fresh render. The same pattern scales to the whole site, and it matches the repo's other
committed-generated-artifact precedent (`apps/studio/src/api/schema.d.ts`, written by
`npm run gen:api-types`).

**The Studio is untouched.** React 19 + Vite + TypeScript stay exactly as they are.

### 2.2 Reuse, concretely

Every reference surface on the site is generated from an authoritative source. The site
cannot drift from the product, because the site *is* the product's source, rendered.

| Site content | Source of truth | Drift possible? |
|---|---|---|
| MCP tool reference (30 tools) | `packages/core/.../contract.py` `TOOL_SPECS` (already contract-tested against the live FastMCP registry) | No |
| Connector catalog (17 presets) | `packages/connectors/.../catalog.py` | No |
| ODI entity JSON schema | `packages/core/.../schema.py` | No |
| Opportunity formula | `packages/core/.../models.py` | No (already test-pinned) |
| CLI command tree | `apps/cli/.../cli.py` (Typer registry) | No |
| All guide prose | `docs/*.md`, rendered verbatim | No |
| Palette, type scale, radii, easings | `apps/studio/src/styles/theme.css` — **read one-way, Studio unchanged** | No |
| Install / quickstart blocks | `README.md` | No |
| License / status | `LICENSE`, `README.md` | No |

## 3. Goals / Non-Goals / Anti-Goals

### Goals

1. Make the product **legible in one screen**: a PM lands cold and understands what this
   is, in the time it takes to read a headline.
2. **Demonstrate, not describe.** The hero proves the thesis by running it.
3. Carry **every detail a user needs** — the landing narrative plus a complete docs hub
   and a generated API reference.
4. Look like the product. The site and the Studio share one palette, one type scale, one
   motion language, so the site reads as the front door of the Living Studio.
5. **Never lie.** Every number, name, and link is generated from or verified against
   source.

### Non-Goals

- A blog, a changelog feed, search, i18n, analytics, cookies, or a CMS.
- A custom domain (decision 7).
- Any change to the Studio's stack, architecture, or runtime behavior.
- Rebuilding the product's design system. The site **consumes** it.

### Anti-Goals

- **No vaporware.** No fake screenshots. The demo is scripted and says so.
- **No dates, no milestones, no roadmap theater.** The roadmap is checkmarks of shipped
  work only.
- **No dead ends.** Every CTA resolves: local quickstart, hosted Studio, GitHub, Issues.
  Auth-gated surfaces are labeled *before* the click, never after.
- **No emoji.** House rule, unchanged.
- **No invented testimonials, logos, customer counts, or benchmarks.**
- **No third-party requests.** No webfonts, no CDN, no analytics, no social scripts.
- **No invented auth schemes.** Never document a token header we do not have.

## 4. Audience & Jobs-to-be-Done

**Primary — product managers / innovation leads.** Landing cold from a link. Skeptical of
AI-tool marketing.
> When I open this page from a link in Slack, I want to see a real product doing a real
> thing within one screen, so I can decide to spend five minutes on it or leave without
> guilt.

**Secondary — AI/agent developers.** Evaluating what to wire an agent to.
> When I'm deciding what context to give my agents, I want the exact endpoint, the exact
> tool names, and a copy-paste quickstart that works locally, so I can try it without
> talking to anyone.

**Tertiary — the sharing PM.** Forwarding the link to a team or a boss.
> When I forward this page, I want it to frame the thesis — evidence over opinion —
> credibly and soberly, so the conversation starts from the idea.

## 5. Design system

Dark-only. The site reads as the front door of the Living Studio, so it uses the Studio's
own tokens verbatim. `website/tools/extract.py` parses
`apps/studio/src/styles/theme.css` and emits `website/dist/assets/tokens.css`. **One-way
read: the Studio is never modified.**

### 5.1 Tokens

```css
:root {
  color-scheme: dark;

  --bg:          #0a0b0e;   /* canvas */
  --bg-raised:   #0e1014;   /* panels */
  --bg-sunken:   #060709;   /* wells, code */
  --text:        #f1f2f4;
  --muted:       #a2a7b3;
  --faint:       #71767f;

  --accent:        #8b8cf8;
  --accent-strong: #6366f1;
  --accent-ink:    #0a0b0e;  /* text on an accent fill */
  --green:       #4ade80;
  --amber:       #f0b34a;
  --red:         #f87171;

  --line:         rgba(255, 255, 255, 0.07);
  --line-strong:  rgba(255, 255, 255, 0.14);
  --surface:      rgba(255, 255, 255, 0.03);
  --surface-hover:rgba(255, 255, 255, 0.06);
  --glass:        rgba(255, 255, 255, 0.045);
  --glass-blur:   blur(20px) saturate(180%);
  --hairline:     inset 0 1px 0 rgba(255, 255, 255, 0.06);

  --ease-out:     cubic-bezier(0.16, 1, 0.3, 1);
  --ease-spring:  cubic-bezier(0.175, 0.885, 0.32, 1.22);
  --ease-tactile: cubic-bezier(0.2, 0.8, 0.2, 1);

  --font: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif;
  --mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, monospace;

  --r-sm: 8px;  --r-md: 12px;  --r-lg: 16px;
  --r-xl: 22px; --r-pill: 999px;

  --gutter:   clamp(20px, 5vw, 48px);
  --section-y: clamp(96px, 13vw, 200px);

```

Spacing is a 4px scale expressed per-component (the Studio has no formal scale and the
site does not need one). Radii mirror the Studio's set.

### 5.2 Type

Zero webfonts — system stack only, same as the Studio.

| Role | Size | Weight / tracking |
|---|---|---|
| Display (hero) | `clamp(2.75rem, 7.5vw, 6rem)` | 600, `-0.04em`, lh 0.98 |
| H2 | `clamp(1.875rem, 4vw, 3.25rem)` | 600, `-0.03em`, lh 1.06 |
| H3 | `clamp(1.25rem, 2vw, 1.75rem)` | 600, `-0.02em`, lh 1.15 |
| Lead | `clamp(1.0625rem, 1.5vw, 1.375rem)` | 400, lh 1.5, `--muted` |
| Body | `1.0625rem` | 400, lh 1.65 |
| Small | `0.9375rem` | 400, lh 1.6 |
| Eyebrow / label | `0.6875rem` | 600, `0.18em`, uppercase, `--faint` |
| Code | `0.9375rem` mono | lh 1.55 |

The Studio's `hero__line` uses weight 600 with `-0.03em`; the site scales that up rather
than inventing a new voice.

### 5.3 Layout

- Page width `--w-page` (1200px); wide sections `--w-wide` (1440px); prose `--w-prose` (68ch).
- Section padding-block `--section-y`.
- Hairline borders only. Radius `--r-md` cards, `--r-lg` panels, `--r-xl` composer-style
  pills, `--r-pill` chips.
- One idea per screen. A section is a screen, not a wall.

### 5.4 Signature moves

1. **Depth without imagery.** The canvas carries the Studio's own two radial indigo
   gradients (`radial-gradient(760px 420px at 50% 108%, rgba(99,102,241,.09), …)` and
   `radial-gradient(900px 520px at 68% -12%, rgba(99,102,241,.08), …)`).
2. **Glass.** `--glass` + `--glass-blur` + `--hairline` top highlight on the hero frame,
   the demo frame, and the sticky header.
3. **Scroll-linked lens reveals.** Surfaces dock beside the narrative as you scroll —
   the Studio's own Rail + Lens metaphor, applied to the page.
4. **The formula as typography.** `Opportunity = Importance + max(Importance − Satisfaction, 0)`
   rendered as a real equation, gap term in `--accent`, with an animated
   importance/satisfaction gap bar.
5. **The six ODI cards, rendered for real.** Not screenshots — faithful recreations of
   the shipped `apps/studio/src/ui/catalog.ts` cards in the site's CSS.
6. **Terminal-dark code.** Code is always dark (`--bg-sunken`), with working copy buttons.

### 5.5 Motion

| Element | Motion |
|---|---|
| Hero entrance | eyebrow → H1 → sub → CTAs, fade-up + `blur(2px) → blur(0)`, 700ms `--ease-out`, 90ms stagger |
| Section reveal | opacity 0→1, `translateY(24px) → 0`, 800ms `--ease-out`, `IntersectionObserver` at 15% |
| Buttons | 150ms `--ease-tactile`; hover `translateY(-1px)`, active `scale(.98)` |
| Demo typing | caret blink 1s `steps(1)` infinite |
| Demo surface | materialize, 600ms `--ease-spring` |
| Copy button | label → "Copied" for 1.5s, announced via `aria-live="polite"` |

**No-JS safety:** content is **visible by default**. The observer *opts content into* the
hidden state only after it loads, so a reader without JS never sees hidden text.

**`prefers-reduced-motion: reduce`:** every transform, stagger, and reveal is removed;
content is immediate.

## 6. Information architecture

```
/                        landing
/docs/                   hub index
/docs/cli/               ← docs/cli.md
/docs/mcp/               ← GENERATED: 30 tools, signatures, arguments
/docs/connectors/        ← docs/connectors.md + GENERATED 17-preset table
/docs/studio/            ← docs/living-studio.md
/docs/architecture/      ← docs/architecture/README.md + data-flow.md
/docs/deployment/        ← docs/deployment.md
/docs/installation/      ← docs/installation.md
/docs/local-llm/         ← docs/local-llm.md
/docs/development/       ← docs/development.md
/docs/roadmap/           ← docs/roadmap.md
/404.html                self-contained
/sitemap.xml  /robots.txt
```

- Every path is **relative** so the site works under the project-Pages base
  `/agentic-odi/`, on a local static server, and on any future domain. `og:url`,
  `og:image`, and `rel=canonical` are **absolute**.
- Each docs page ends with a **"Source of truth: `docs/cli.md` — view on GitHub"** link,
  so the repo stays visibly authoritative. The site is a rendering, not a fork.
- `404.html` is fully self-contained (inline styles, absolute home link) because Pages
  serves it at arbitrary depths where relative assets break.
- `sitemap.xml` and `robots.txt` are added — the site is now multi-page, so the
  single-page era's "no sitemap" ruling is reversed.

3. **Steer.** The team decides from the same picture: scored outcomes, opportunity

## 8. The interactive demo

The credibility gap the site cannot close with a static image: the repo has **no
screenshots**. The demo is the substitute, and it must be honest about being one.

### 8.1 Frame

A device frame — a browser-less app window, since the Studio is a Tauri desktop app —
rendering the Studio's exact chrome:

- The `.bar`: wordmark left, health pill right.
- The transcript area.
- The `.composer__shell` pill: rounded 22px, `--surface` fill, 34px circular send button.

Backed by `--glass` + `--glass-blur` + a 1px `--line-strong` hairline, with a deep shadow
(`0 40px 120px -20px rgba(0,0,0,.85)`) so it floats off the canvas.

### 8.2 Script

Three exchanges, selectable by suggestion chips (real `<button>`s) or by typing. Each ends
with the agent composing a real catalog card.

| # | Prompt | Composed card |
|---|---|---|
| 1 | "A customer told us they still reconcile invoices by hand every Friday." | `outcome-card` — importance 8, satisfaction 3, opportunity 13.0 |
| 2 | "Which of these should we build first?" | `opportunity-board` — three ranked outcomes |
| 3 | "Show me the job behind that." | `job-map` — four steps of the job-to-be-done |

The agent "types" with a blinking caret, then the card materializes on `--ease-spring`.
The data is plausible and internally consistent, and the opportunity score is computed
with the **real formula** so the numbers are not decorative.

### 8.3 Honesty

Immediately above the frame:

> **Scripted preview.** These are canned responses from a fixed script. The live Studio
> talks to a real MCP server.

with a **"Open the live Studio"** link beside it. This is a hard requirement, not a
nicety: a demo that looks real but isn't is the single most damaging thing this site
could ship.

### 8.4 Constraints

- **No network calls.** No fetch, no analytics, no external requests.
- **No-JS fallback:** the demo degrades to a **static, fully readable transcript** of the
  three exchanges, with the composed cards rendered server-side. The page is complete
  and useful without JavaScript.
- Keyboard operable: chips are buttons; the composer is a real `<textarea>`; `Enter`
  submits, `Shift+Enter` newlines.
- Respects `prefers-reduced-motion`: the typing and materializing become instant.
- The script lives in `website/content/demo.yaml` so it is editable without touching JS.

## 9. The docs hub

### 9.1 Verbatim mirroring, plus a web-native layer

Guide prose is rendered **verbatim** from `docs/*.md`. One source of truth, zero drift.
On top of that, the hub adds what a web reader needs and a repo file cannot provide:

- A **hub index** grouping the guides by job: *Get started* (Quick start, Installation,
  Living Studio, Local LLM), *Build* (CLI, Connectors, MCP reference, Architecture),
  *Operate* (Deployment, Development, Roadmap).
- **A Quick start page** — a web-native path from zero to a running studio, assembled
  from `README.md` and `docs/installation.md`, with the install tabs.
- **The generated reference** (§10).
- **Web navigation** — a persistent sidebar on docs pages, plus prev/next.
- **A "source of truth" link** on every page.

### 9.2 Markdown pipeline

`markdown-it-py` with `html=False` (no raw HTML pass-through from repo docs — XSS-safe
by construction), `linkify=True`, and tables enabled. Fenced code blocks are highlighted
server-side with **Pygments** using a dark style, so highlighting costs **zero client-side
JavaScript**.

Heading anchors are generated with GitHub-compatible slugs, so a link into a doc page's
heading works.

### 9.3 The `docs/living-studio.md` problem

`docs/living-studio.md` is 360 lines of desktop/Tauri detail — correct but dense. The hub
gives it a **Studio landing page** in front of it that orients the reader (what it is,
the three run modes, the first-run flow) before the reference detail.

## 12. Accessibility, performance, and the test contract

### 12.1 Accessibility (WCAG 2.1 AA)

- Semantic landmarks (`header` / `nav` / `main` / `footer`); **exactly one `<h1>` per
  page**, inside `<main>`; no skipped heading levels.
- `lang="en"`, viewport meta, a skip link to `#main`.
- Contrast: every text pair ≥ 4.5:1, every UI boundary ≥ 3:1, on `--bg`, `--bg-raised`,
  and `--bg-sunken`. The Studio's own palette is not automatically AA on `--faint`
  (`#71767f` on `#0a0b0e` ≈ 4.0:1) — the site uses `--faint` **only** for large text and
  non-essential decoration, and uses `--muted` (`#a2a7b3`, ≈ 7.4:1) for small body text.
  This is a deliberate, documented deviation from the app's usage.
- Full keyboard operability. Focus ring: 2px `--accent` with 2px offset, never removed.
- Copy controls are real `<button>`s with accessible names; "Copied" announced via
  `aria-live="polite"`.
- Decorative SVG `aria-hidden="true"`; meaningful SVG carries `role="img"` + `<title>`.
- The demo's transcript and the docs' prose are readable with JavaScript disabled.
- `prefers-reduced-motion` fully honored.
- Tested at 360px width with no horizontal scroll.

### 12.2 Performance

- **Zero third-party requests. Zero webfonts. Zero analytics. Zero cookies.** The page
  talks only to its own origin.
- Budget per page: HTML ≤ 60 KB, CSS ≤ 40 KB, JS ≤ 25 KB total, total transfer
  ≤ 200 KB. `og.png` ≤ 300 KB.
- No layout thrash: reveals use `transform` and `opacity` only.
- Lighthouse ≥ 95 across Performance / Accessibility / Best Practices / SEO.

### 12.3 Test contract

## 15. Risks & Mitigations

1. **The site contradicts in-flight Studio work.** An approved "Intent-First PM
   Experience" spec (local, unmerged) renames canvas views — *Opportunity Landscape* →
   *Opportunity Thesis* — and adds a "What I've learned" memory panel.
   **Mitigation:** the site names **catalog cards** (a stable contract), never canvas
   view names, and generates all product surface content from source. Narrative copy
   stays at the framework level. See §16.
2. **The generated reference goes stale.** **Mitigation:** `test_content_sync.py` fails
   CI on drift. The generator is the only way to change the site.
3. **The docs hub is a wall of text.** **Mitigation:** the hub index groups by job, a
   web-native Quick start leads, and `docs/living-studio.md` gets an orienting page.
4. **A demo that looks real but isn't.** **Mitigation:** the "Scripted preview" label is
   a test-pinned contract string, above the frame, beside a live link.
5. **Markdown rendering mangles the repo docs** (tables, nested lists, long code
   fences). **Mitigation:** render the full `docs/` corpus in the generator and diff
   against expectations; `markdown-it-py` with `html=False` handles all constructs
   present in `docs/`.
6. **A second source of truth creeps in.** **Mitigation:** no prose is written twice. The
   only hand-written copy is `website/content/*.yaml` for the landing page; every guide
   is rendered from `docs/`.
7. **Relative paths break at depth.** **Mitigation:** the generator computes a `depth`
   per page and prefixes every asset and link. `test_site.py` asserts each page's links
   resolve on disk.
8. **A pre-existing repo test fails** —
   `apps/studio-api/tests/test_studio_connectors_router.py::test_unknown_route_is_404`
   fails on a clean `main` (the SPA fallback returns 200 for unknown `/api` routes).
   **Not caused by this work and deliberately left alone**; noted so it is not
   misattributed.

## 16. Relationship to the in-flight "Intent-First PM Experience" work

An approved-but-unimplemented design (`docs/superpowers/specs/2026-10-21-intent-first-pm-experience-design.md`)
moves the Studio toward a PM-first, intent-first product: the **Opportunity Thesis**
replaces the Opportunity Landscape as the central artifact, ODI vocabulary retreats
behind an expert view, and a "What I've learned" memory panel is added.

That work is **not in scope for this site redesign**, and the site is built against
`main` as it stands. But the site must not contradict it. Three rules follow:

1. The site names **catalog cards** — `outcome-card`, `opportunity-board`,
   `impact-simulation`, `evidence-quote`, `job-map`, `decision-record` — which are the
   agent's closed catalog and a stable contract. It does **not** name canvas views.
2. The site keeps the **ODI thesis** at the top: the framework is the engine, the
   product is the interface. That framing is compatible with intent-first, which
   explicitly keeps "ODI as the engine, never the greeting."
3. Any product-surface fact on the site is **generated from source**, so when
   intent-first lands and renames a view, the site follows on the next build rather
   than contradicting it.

The local WIP that backed this decision is preserved on the branch
`wip/preserve-local-work-2026-10-22`.
