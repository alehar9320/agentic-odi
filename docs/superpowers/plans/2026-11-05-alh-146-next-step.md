# ALH-146 · M0-14 — The product remembers why you came back

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:executing-plans` — this harness exposes no subagent dispatch tool for implementation work. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one store entity, `NextStep`, that survives a reload and a cache clear, is offered in-thread at the end of a productive turn, and turns a returned visit's "did it happen?" answer into an ordinary `Evidence` row.

**Architecture:** `NextStep` is a core repository entity (Pydantic model → event-sourced `SQLiteRepository` → `ODIService`), not a browser or sidecar-local table, because resolving it must write a core `Evidence` row that links back to it. The sidecar exposes three routes over the service; the Studio reads the open step through them and renders it in the existing Hero greeting and in a dock-mounted, dismissible aside cloned from `GuidanceHint`.

**Tech stack:** Python 3.10+ / Pydantic v2 / FastAPI / Typer / FastMCP; React + TypeScript + vitest; Playwright (already a devDependency with a working `e2e/` harness).

**Spec:** Linear ALH-146 (`value/outcome`, `area/studio`,`area/studio-api`,`area/core`, size M, `Depends on M0-09` = ALH-142 = Done).

## Global constraints

- Branch from `origin/main`. Base of this plan: `f0f56269`.
- The threshold-style rule for this slice: **one open next step per workspace**, enforced in the service by stamping `superseded_at` on the previous row. Never delete, never a unique index (the row must survive as history).
- `overdue`/age is computed at read time from `created_at`, never stored (`lib/relativeTime.ts:8` `formatRelativeTime` is the only relative-time helper; adding a second one is forbidden by `docs/architecture/reuse.md`).
- Resolving writes an ordinary `Evidence` row with `source_kind='manual'`, `item_type='manual'`, `origin='user'`, `raw={'next_step_id': <id>}`. No `resolution` table.
- Never invent what the user did: an unresolved step stays unresolved and the greeting says so.
- The prompt is a suggestion in the thread, never a modal, and it never blocks a turn.
- "No fabricated data": with no step on a fresh store the greeting is the existing one, unchanged.
- Docs land in the same PR: `docs/living-studio.md` (new surface), `README.md` (new command), `docs/cli.md` (new command group), `docs/roadmap.md` ticked.
- `scripts/doc_check.py:235` `missing_routes` requires every documented route to be actually served — routes land before or with the doc edit, never after.

The "prove the entity is wired everywhere" obligation is met by extending `apps/cli/tests/test_persistence.py`, which already does a write-then-reopen round-trip per entity. ## Review Focus

The five classes of input this spec implies and no existing test covers:

1. **A step whose `resolution` is set but which was never resolved** (hand-edited store, replay of a partially-written event): reading it must not render a fake "did it happen" success. Task 1 pins it.
2. **A second `NEXT_STEP_CREATED` event replayed against a store that already has an open step** — replay must reproduce exactly one open step, so supersede must live in the event stream, not only in the service. Task 2 pins it.
3. **`GET /api/next-step` on the MCP-passthrough backend** with no step: it must return "nothing yet", not an empty list that the greeting reads as a step with blank text. Task 4 pins it.
4. **A stored step from a browser reload where the sidecar is down or the id is unknown**: the greeting must fall back to the existing copy rather than greeting "Last time you said you would  (0d ago)". Task 5 pins it.
5. **Dismissing the prompt**: it is remembered for the session only — the next session must offer it again. Task 6 pins it, and calls out where this differs from `GuidanceHint`'s permanent localStorage dismissal.
