# Design: agentic-odi GitHub Pages marketing site

## Intent & Why
Ship a customer-facing GitHub Pages site for agentic-odi (an experimental MCP-based testbed for Outcome-Driven Innovation). Audience: product managers, innovation teams, and AI/agent developers. The site answers why/what/how/when with a Jobsian sensibility: one page, ruthless focus, empathy for the user's pain, craft in typography and motion, no jargon soup, one obvious CTA. The bar: what a principal CTO under Steve Jobs would ship.

## Goals
- One scrollable landing page that converts a curious PM/eng lead into trying the hosted demo or cloning the repo.
- Communicate the core insight: "stop shipping guesses; ground agents in verified customer outcomes."
- Feel state-of-the-art: fast, accessible, beautiful type, subtle tasteful motion, dark-mode-aware, perfect on mobile.
- Deploy automatically to GitHub Pages on push to main via GitHub Actions.

## Non-Goals / Anti-Goals
- NOT a docs site (no MkDocs/Docusaurus), no blog, no nav maze.
- NOT claiming OSS license (repo has none — all rights reserved) or overstating maturity (site must carry honest "experimental" framing).
- NOT a framework-heavy build: no React/Next/Astro. Hand-crafted static HTML + CSS + minimal vanilla JS. Zero runtime deps, Lighthouse 95+.

## Constraints
- Source lives in `website/` at repo root (`docs/` is reserved for internal specs; `/site` is gitignored so use a different output path or force-add strategy — prefer keeping sources directly deployable, i.e., Pages serves `website/` contents via actions/upload-pages-artifact).
- Deploy workflow: `.github/workflows/pages.yml` using actions/upload-pages-artifact + actions/deploy-pages; triggers on push to main paths `website/**` and the workflow itself.
- No visual assets exist in repo. Site must include: hand-designed minimal SVG wordmark ("agentic odi" + simple geometric mark), favicon (SVG), OG/Twitter card image (1200×630 — generate as static SVG or HTML-drawn; note OG images on Pages need a real raster ideally — plan an SVG for favicon/inline and either a committed PNG generated by a tiny script or an SVG OG fallback).
- Copy honesty: cite the ODI ~86% success-rate claim carefully ("as reported by Strategyn/ODI literature"), frame product as experimental, hosted endpoint requires auth.
- Fonts: system font stack (-apple-system / SF Pro on Apple, Segoe, etc.) — no webfont downloads; typographic craft via weight/tracking/scale.
- Dark/light via prefers-color-scheme.
- Accessibility: semantic landmarks, contrast AA+, reduced-motion respect.

## Page structure (Jobsian narrative)
1. Hero: the enemy = the guess. Headline direction: "Your roadmap is a guess." Sub: one sentence on grounding AI agents in verified customer outcomes. Single CTA (Try the hosted demo) + secondary (View on GitHub).
2. The Problem: shipping features nobody needs; the cost of opinion-driven development. Short, punchy, maybe a 3-beat parallel structure.
3. The Insight: what ODI/JTBD is in ~3 plain sentences + the outcome-satisfaction/opportunity-score idea visualized simply (e.g., a small CSS/SVG quadrant or bar showing Opportunity = Importance − Satisfaction). Stat callout with citation caveat.
4. How it works: 3 steps — capture jobs & outcomes in the MCP server; agents query the outcome database (MCP tools); PMs steer in The Living Studio. Small code/terminal snippet for the MCP endpoint. Screenshot placeholder for Living Studio (no screenshots exist — plan a tasteful illustrative SVG/CSS mock of the UI rather than a fake screenshot).
5. For builders: MCP endpoint, install one-liner (uv sync --all-packages; python -m client.run), links to repo.
6. Honest status: experimental badge, what works today, roadmap framing (when).
7. Footer: copyright (no license), links, "Built with outcomes, not guesses."

## What's left to the builder
Exact CSS scale/spacing system, exact copy micro-polish, SVG mark design details, animation choreography choices, workflow YAML specifics.
